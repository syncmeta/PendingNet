# PendingNet 0.3.39

This release adds the management console and fixes macOS system DNS routing in TUN mode. The macOS and iOS app build number is 340.

- Adds a separate management tab, with independent local-only administrator credentials, user and first-seen IP information, scoped pairing-link issuance and revocation, and Android/Windows sing-box configuration export.
- Improves active-connection latency measurements, server protocol selection, locally assigned server names, and the connection controls.
- Adds English localization for the macOS and iOS client interfaces and common errors.
- Adds server-side per-link users and first-seen source IP recording, with compatibility for existing server state.
- Routes macOS system DNS through a local sing-box DNS entry while TUN is active, and restores the previous DNS settings when leaving TUN or stopping the engine. Disabled DNS protocols are excluded from ownership.

**Not included:** editing and restarting the live PendingNet server configuration. The production configuration write endpoint remains disabled (HTTP 503). The management API requires an updated PendingNet Server and a separately issued administrator pairing link; publishing the server binary does not install it on existing VPS hosts. iOS builds are distributed separately through TestFlight.

Validation includes core automated tests and a manual macOS DNS capture showing system A/AAAA queries reaching the local DNS entry over a short TUN window. This does not cover every server/protocol combination, restart or network-interface change. The DNS ownership fix is macOS-specific.

The macOS package requires macOS 14 or later and a separately deployed PendingNet Server plus a valid pairing link. The app bundles its proxy engine; first use of system proxy or TUN may require enabling PendingNet under System Settings → General → Login Items & Extensions. Exported client configs and pairing links contain credentials: keep them private.
